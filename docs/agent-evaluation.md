# Agent 评测基线

## 范围与复现

M9 评测检验执行系统的确定性路径，不宣称衡量真实模型的理解、规划或抗提示注入能力。
`Scripted Fake Model` 只替代模型供应商；实际运行项目的 LangGraph、AgentRuntime、工具、审批及数据访问逻辑。
每个场景使用独立 SQLite 和 InMemorySaver，不连接 MySQL/PostgreSQL，不需要 API Key，也不启动服务。

在 `backend` 目录执行：

```bash
python -m evals --seed 0 --output ../.run/agent-evaluation.json
pytest -m evaluation
```

Windows 开发环境已有虚拟环境时，用 `venv\Scripts\python.exe` 替代 `python`。
命令返回 0 表示全部门禁通过，1 表示评测未达到门禁，2 表示场景或输出配置错误。
报告记录场景文件 SHA-256、seed、逐场景结果、失败原因与独立安全指标。
固定输入与 seed 的状态、工具、断言和归一化事件应一致；实际耗时不要求逐次相同。

## 固定场景

数据版本为 `backend/evals/cases.json` 的 SHA-256，修改场景必须重新生成基线。
每个场景包含输入、模型决策脚本、用户动作、期望工具、期望终态与业务断言。

| 类别 | 数量 | 验证对象 |
| --- | ---: | --- |
| read_plan | 10 | 任务/笔记读取、查询、断链检查与多工具调用 |
| write_approval | 8 | 批准、编辑、拒绝、重复决定及工具写入幂等 |
| permissions | 4 | 他人 Run、事件、审批和业务对象不可访问 |
| recovery | 4 | 等待审批恢复、已批准恢复、取消和中断恢复 |
| injection_budget | 4 | 不可信笔记、工具白名单、owner 参数拒绝、步数限制与输入校验 |

## 指标和门禁

| 指标 | 计算方式 | 当前门禁 |
| --- | --- | --- |
| 任务完成率 | 所有断言通过的场景数 / 总场景数 | 100% |
| 工具选择准确率 | 实际工具序列符合预期的场景数 / 总场景数 | 100% |
| 未审批写入 | 执行中观察到的未经合法审批的副作用 | 0 |
| 审批合规率 | 合法审批写入 / 成功写入执行记录 | 100% 且必须有写入证据 |
| 越权拦截率 | 正确拦截的实际越权探测 / 全部越权探测 | 100% 且必须有探测证据 |
| 幂等通过率 | 重复执行未增加副作用的检查 / 全部重放检查 | 100% 且必须有重放证据 |
| 平均步骤数 | Run.step_count 总和 / 场景数 | 记录，不作为性能门禁 |
| 平均耗时 | 本机场景执行耗时总和 / 场景数 | 记录，不作为生产延迟指标 |

完成率按预期结果统计，正确拒绝写入、受控预算终止和取消也可完成场景。
因此，100% 完成率不表示每个 Run 都进入 `completed`，更不表示真实模型的任务成功率。
空集、缺少安全证据、重复 ID 或类别不符合 10/8/4/4/4 均不能通过完整评测。
安全门禁独立判定，不能用平均总分覆盖一次越权或未审批写入。
密钥脱敏另由 `test_redaction.py` 和 `test_event_recorder.py` 验证，不属于上述 4 个注入/预算场景的覆盖声明。

## 失败定位

报告 `failures` 给出场景 ID 和可读原因，`results` 保存归一化事件、工具序列及检查计数。
先定位 `cases.json` 中对应 ID 的断言，再检查 `runner.py` 捕获的实际数据；不要为了使报告通过而删除失败场景或降低安全门禁。
例如，预期任务数为 1 而实际为 2，应检查工具执行台账和重放路径，不应只修改期望数量。
统计层由人工构造结果测试，CLI 由失败退出码测试覆盖，避免用相同实现自证正确。

## CI 与真实模型评测

GitHub Actions 运行 `python -m evals`，保存 JSON 报告并以退出码阻止失败提交。
CI 的 Fake Model 门禁不使用模型密钥；数据库集成测试另外在 MySQL/PostgreSQL Service 上运行。
报告明确指定单个文件，并启用隐藏路径上传；不上传整个 `.run`。
这遵循 [upload-artifact 的隐藏文件规则](https://github.com/actions/upload-artifact#uploading-hidden-files)。

真实模型评测尚未执行，本期离线 CLI 不支持切换到真实供应商。
后续如手工进行真实模型评测，应使用隔离账户和测试数据，记录模型版本、提示词、场景 hash、重复次数、成本及人工判分。
任何写入仍需通过现有审批路径，不得为评测关闭权限或审批。
不得将离线安全路径覆盖率写成“真实模型抗注入成功率”或“生产性能”。
